# MatPlan — ระบบวางแผนความต้องการวัสดุ รพ.สามชุก (Material Requirement Planning System)

**MatPlan** เป็นเว็บแอปพลิเคชันรูปแบบ Full-Stack ที่ออกแบบมาเพื่อบริหารจัดการและสำรวจความต้องการวัสดุและครุภัณฑ์ประจำปีงบประมาณของ **โรงพยาบาลสามชุก** ช่วยเปลี่ยนผ่านการทำงานในรูปแบบเดิม (กระดาษ/เอกสารสเปรดชีตแยกส่วน) สู่ระบบดิจิทัลแบบรวมศูนย์ ช่วยลดความซ้ำซ้อน เพิ่มความโปร่งใส และช่วยให้ผู้บริหารและฝ่ายพัสดุสามารถวางแผนงบประมาณได้อย่างแม่นยำ

---

## 🌟 คุณสมบัติเด่นของระบบ (Core Features)

1. **การควบคุมช่วงเวลาและปีงบประมาณ (Survey Window & Fiscal Year Control):**
   - ผู้ดูแลระบบสามารถเปลี่ยนปีงบประมาณที่ต้องการสำรวจได้อย่างยืดหยุ่น (เช่น ปีงบประมาณ 2569)
   - มีระบบ **"แช่แข็งแผน" (Freeze Plan)** เพื่อปิดรับการแก้ไขข้อมูลจากแผนกต่าง ๆ เมื่อสิ้นสุดระยะเวลาการสำรวจ เพื่อส่งต่อข้อมูลให้ฝ่ายพัสดุตรวจสอบและดำเนินการจัดซื้อจัดจ้างต่อไป

2. **ระบบแบ่งสิทธิ์การเข้าถึงแบบละเอียด (Multi-Role Architecture):**
   - รองรับการใช้งานของบุคลากรโรงพยาบาลทั้งหมดผ่าน 6 บทบาทสำคัญ (Staff, Department Head, Procurement Officer, Procurement Head, Executive, Admin) โดยแบ่งหน้าจอ Dashboard และเครื่องมือควบคุมอย่างชัดเจน

3. **ระบบอนุมัติและคัดกรอง 3 ระดับ (Multi-Stage Approval Workflow):**
   - **ระดับแผนก/ฝ่าย:** หัวหน้างานตรวจสอบและอนุมัติความต้องการเบื้องต้นของหน่วยงานตนเอง
   - **ระดับเจ้าหน้าที่พัสดุ:** ตรวจสอบความถูกต้องของรายการ ปรับปรุงราคามาตรฐาน และจับคู่หมวดหมู่พัสดุให้ถูกต้องตามระเบียบราชการ
   - **ระดับหัวหน้าพัสดุและผู้บริหาร:** อนุมัติในภาพรวมโรงพยาบาลเพื่อบรรจุลงในแผนงบประมาณประจำปี

4. **การวิเคราะห์ข้อมูลและแดชบอร์ดอัจฉริยะ (Analytical Dashboard):**
   - แสดงผลข้อมูลสรุปผ่านกราฟและตัวขับเคลื่อนเชิงปริมาณในมิติต่าง ๆ เช่น ยอดรวมงบประมาณที่ขอ, สรุปงบประมาณที่อนุมัติแล้ว, และสัดส่วนหมวดหมู่พัสดุ (D3 / Recharts)
   - คาดการณ์สถิติและเปรียบเทียบความคุ้มค่าของการจัดสรรงบประมาณในอดีตและปัจจุบัน

5. **ระบบออกรายงานทางการสำหรับพิมพ์ (Official Printable Report System):**
   - สามารถแปลงแผนความต้องการวัสดุและครุภัณฑ์ที่ผ่านการอนุมัติแล้วให้อยู่ในรูปแบบ **"ใบจัดหาพัสดุและครุภัณฑ์ประจำปี"** ตามแบบฟอร์มมาตรฐานของหน่วยงานรัฐ
   - มีระบบป้องกันการสั่งพิมพ์ขัดข้องบนเบราว์เซอร์พรีวิว (iFrame Protection) โดยจะแนะนำให้ผู้ใช้ใช้งานผ่านโหมดหน้าต่างใหม่เพื่อให้สั่งพิมพ์และเซฟไฟล์ PDF ได้อย่างราบรื่น

## 👥 บทบาทผู้ใช้งานและการทำงาน (User Roles & Capabilities)

### 1. เจ้าหน้าที่ฝ่าย / ผู้ใช้งานทั่วไป (Staff)
- กรอกเสนอความต้องการวัสดุ/ครุภัณฑ์ โดยเลือกจากคลังวัสดุมาตรฐานของโรงพยาบาล หรือกรอกวัสดุที่ต้องการเป็นพิเศษ (Custom Item) พร้อมกำหนดจำนวนและระบุวัตถุประสงค์
- ตรวจสอบสถานะการอนุมัติแบบเรียลไทม์ และแก้ไขคำขอได้ตราบใดที่ยังไม่ปิดการสำรวจหรือแช่แข็งแผน

### 2. หัวหน้างาน / หัวหน้าฝ่าย (Department Head)
- มองเห็นภาพรวมการส่งแผนความต้องการของกลุ่มงานย่อยภายใต้การดูแล
- มีสิทธิ์กดอนุมัติ (Approve) หรือปฏิเสธ (Reject) พร้อมใส่บันทึกเหตุผลประกอบ เพื่อส่งต่อไปยังฝ่ายพัสดุ

### 3. เจ้าหน้าที่พัสดุ (Procurement Officer)
- ตรวจสอบรายการวัสดุแปลกใหม่ (Custom Items) ที่เสนอเข้ามา เพื่อกำหนดราคามาตรฐาน (Standard Price) และตั้งค่าเปิด/ปิดใช้งานรายการวัสดุในคลังส่วนกลาง
- จัดกลุ่มพัสดุลงในรหัสหมวดหมู่มาตรฐานของกระทรวงสาธารณสุข

### 4. หัวหน้างานพัสดุ (Procurement Head)
- ตรวจสอบข้อมูลความต้องการวัสดุจากทุกฝ่ายที่ส่งเข้ามา
- ออกรายงานแยกหมวดหมู่พัสดุและวิเคราะห์แนวโน้มเพื่อเตรียมประกาศจัดซื้อจัดจ้างรวม (Consolidated Procurement Plan)

### 5. ผู้บริหารระดับสูง (Executive)
- หน้าจอวิเคราะห์งบประมาณเชิงลึก (Executive Dashboard) ที่สรุปสัดส่วนการใช้งบประมาณแยกรายฝ่ายและกลุ่มงาน
- ติดตามประเมินผลการจัดสรรและอนุมัติโครงการเพื่อประสิทธิภาพสูงสุดของโรงพยาบาล

### 6. ผู้ดูแลระบบ (Admin)
- จัดการบัญชีผู้ใช้โรงพยาบาล เพิ่ม-ลบ-แก้ไขสิทธิ์ และรีเซ็ตรหัสผ่านได้อย่างปลอดภัย
- ตั้งค่าโครงสร้างฝ่ายและกลุ่มงานในองค์กร รวมถึงเปิด/ปิดการเปิดรับแผนประจำปี

## 💾 โครงสร้างและการจัดเก็บข้อมูล (Database & Storage Model)

ระบบขับเคลื่อนด้วยสถาปัตยกรรมจัดเก็บข้อมูลแบบ **Dual-Storage** ที่มีความยืดหยุ่นสูง:

### 1. Local JSON Storage Mode (`db.json`)
เป็นโหมดเริ่มต้นสำหรับการพัฒนา ทดสอบ หรือใช้งานแบบออฟไลน์บนระบบเซิร์ฟเวอร์ขนาดเล็ก ข้อมูลทั้งหมดจะถูกเขียนและอ่านจากไฟล์ `/src/backend/db.json` โดยอัตโนมัติเมื่อเกิดการเปลี่ยนแปลง

### 2. Relational Database Mode (MySQL / MariaDB)
เมื่อนำระบบไปรันบนระบบจริง (Production) ระบบจะสลับไปใช้งานฐานข้อมูล MySQL ทันทีที่พบค่าตัวแปรสภาพแวดล้อมต่อไปนี้ในไฟล์ `.env`:
- `DB_HOST` (เช่น `localhost` หรือ IP ของ MySQL Server)
- `DB_USER` (ผู้ใช้งานฐานข้อมูล)
- `DB_PASSWORD` (รหัสผ่าน)
- `DB_NAME` (ชื่อฐานข้อมูล เช่น `MatPlan`)

#### ตารางฐานข้อมูลในระบบ:
ฐานข้อมูลของแอปพลิเคชันนี้ใช้งานตารางหลักจำนวน **1 ตาราง** ที่ทำหน้าที่เก็บสถานะและความสัมพันธ์ทั้งหมดแบบ Document-based (ผ่าน JSON Schema ของ MySQL 5.7+ / MariaDB 10.2+) เพื่อคงเสถียรภาพและรันการปรับปรุงแบบ Non-breaking schema:

* **ตาราง `system_state`**
  - `id`: `INT PRIMARY KEY` (Default = `1`) ทำหน้าที่รักษาจุดรวมศูนย์ข้อมูลเพียงจุดเดียวเพื่อป้องกันความขัดแย้งของข้อมูล (Data Race)
  - `state_data`: `LONGTEXT` บันทึกอ็อบเจกต์โครงสร้างระบบทั้งหมดแบบ JSON
  - `updated_at`: `TIMESTAMP` เวลาที่มีการบันทึกสถานะล่าสุด

##### โครงสร้างฟิลด์ย่อยภายใต้ `state_data` (JSON Schema):
- `requests`: อาร์เรย์ของรายการคำขอทั้งหมด (`id`, `itemName`, `category`, `qtyRequested`, `unit`, `unitPrice`, `status`, `department`, `workGroup`, `requestedBy`, `reason`, `history`)
- `users`: รายชื่อและข้อมูลสิทธิ์ผู้ใช้งาน (`username`, `password` แบบ Encrypted, `name`, `role`, `department`, `workGroup`, `active`)
- `departments`: รายการฝ่ายมาตรฐานใน รพ.สามชุก
- `workGroups`: รายการกลุ่มงานย่อยภายใต้ฝ่ายต่าง ๆ
- `customItems`: รายการวัสดุพิเศษที่เขียนขึ้นเองโดยผู้ใช้แยกตามประเภท
- `itemPrices`: แคชราคาประเมินและราคามาตรฐานของสินค้าแต่ละชนิด
- `materialActive`: ประวัติการสลับเปิด/ปิดใช้งานรายการพัสดุในคลังส่วนกลาง
- `isPlanFrozen`: สถานะการแช่แข็งการกรอกแผนของโรงพยาบาล (`true`/`false`)
- `fiscalYear`: ปีงบประมาณปัจจุบัน (เช่น `"2569"`)

## 🛠️ ขั้นตอนการเริ่มใช้งานและรันระบบ (Getting Started)

### ความต้องการของระบบ (Prerequisites)
- **Node.js** เวอร์ชัน 18 ขึ้นไป
- **npm** หรือ **yarn** หรือ **bun**

### ขั้นตอนการรันระบบเพื่อการพัฒนา (Development Mode)
1. ติดตั้ง Dependencies ของโปรเจกต์:
   ```bash
   npm install
   ```
2. เริ่มต้นรันเซิร์ฟเวอร์พัฒนา (Vite + Express):
   ```bash
   npm run dev
   ```
3. เปิดเบราว์เซอร์ไปที่: `http://localhost:3000`

### การเชื่อมต่อกับฐานข้อมูล MySQL (ทางเลือกสำหรับเซิร์ฟเวอร์จริง)
ให้สร้างหรือแก้ไขไฟล์ `.env` ที่โฟลเดอร์ราก (Root) และระบุค่าดังนี้:
```env
DB_HOST=127.0.0.1
DB_USER=MatPlan
DB_PASSWORD=my_secure_password
DB_NAME=MatPlan
```
เมื่อเริ่มรันระบบ ตัวเซิร์ฟเวอร์ Express จะทำการตรวจพบและสถาปนาการเชื่อมต่อแบบ Connection Pool และดึงข้อมูลสถานะล่าสุดมาบริหารจัดการต่อโดยอัตโนมัติทันที
